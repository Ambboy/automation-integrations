# Telegram rich-only inbound — 0.1.1

Внешний плагин Hermes для входящего `rich_message` без `text`. Преобразует абзацы и списки в текстовую **копию** Telegram Update и передаёт её штатному обработчику. Ядро Hermes не изменяется.

Проверенный контракт: **Hermes 0.22.5**, core `bf0203a794a07aac3ff764972ab9087baa4e4f4e`, **python-telegram-bot 22.8**. Manifest намеренно ограничивает версию Hermes; будущая совместимость не обещается.

## Установка

1. Проверьте версии и выполните офлайн-тесты ниже.
2. Сохраните адресные резервные копии существующего каталога плагина и настроек. Проверьте отсутствие конфликтующей работы.
3. Поместите только `__init__.py`, `plugin.py` и `plugin.yaml` в `$HERMES_HOME/plugins/automation-telegram-rich-inbound/`. Не копируйте каталог в исходники Hermes.
4. В нужном профиле выполните:

```sh
hermes plugins enable automation-telegram-rich-inbound
```

Штатный enable в проверенной версии поддерживает hot reload. Он может перечитать все плагины выбранного home; перед операцией проверяйте активную работу. Повторный enable уже включённого плагина не обязательно загружает изменённый код. Подтверждайте регистрацию и настоящий входящий сценарий отдельно; не перезапускайте общий gateway без разрешения.

## Проверки

Из корня репозитория, в окружении с установленным Hermes и заданным scratch-каталогом `TMPDIR`:

```sh
python3 -B bridges/hermes_telegram_rich_inbound/run_tests.py
python3 -B bridges/hermes_telegram_rich_inbound/run_tests.py review_probes.ReviewProbes
```

Runner сохраняет bootstrap фактического managed runtime, запрещает сетевые соединения и использует синтетические Telegram identities. Он не устанавливает зависимости и не активирует плагин. Наборы содержат 41 основной тест и шесть исходных независимых reviewer probes.

`SOURCE_MANIFEST.json` фиксирует точные runtime/test bytes. Runtime-код и тесты публикуются без изменений относительно независимо проверенного кандидата 0.1.1; приватные отчёты и переписка не включены.

## Границы безопасности

- Исходный Update, отправитель, чат, тема и message/update IDs сохраняются.
- Доступ, команды, batching и admission/dedup остаются в штатном обработчике.
- Код и цитаты сохраняют видимые границы, чтобы `/stop` внутри них не становился командой. Новая `bot_command` entity создаётся только из полноценного семантического command-узла.
- Обычный неформатированный `/stop` сохраняет стандартное командное поведение Hermes.
- Выбор останавливается на первом совпадении. Недостижимые сторонние filters не выполняются ради проверки совместимости.
- Ошибки и неизвестные элементы отображаются явно; глубина, число узлов и длина ограничены.
- Нет сетевых запросов, модельных вызовов, monkeypatch или модификации приватного cache со стороны runtime-плагина.

## Отключение

```sh
hermes plugins disable automation-telegram-rich-inbound
```

Проверяйте подтверждённую выгрузку callback, а не только значение в конфигурации. После выгрузки можно убрать только каталог этого плагина. Обычный текст продолжает работать; исходный rich-only дефект проверенной версии без расширения возвращается.
