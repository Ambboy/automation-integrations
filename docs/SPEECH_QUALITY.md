# Качество речи: открытые дефекты, 03.10.2026

Подтверждение доставки текста/голоса не являлось приёмкой смысловой подготовки.
Дмитрий сообщил о потере контекста, произношении стрелок как английского `to` и
проблемах иностранных слов. Телефоны, документы и даты им ещё не проверялись.

Воспроизведение без платных API и изменения production:

```bash
PYTHONPATH=. python3 ops/speech_quality_audit.py \
  --hermes-source /home/operator/.hermes/hermes-agent \
  --output docs/SPEECH_QUALITY_AUDIT.json
```

Девять синтетических случаев прошли через настоящий prepare_spoken_text дважды
(как native auto-TTS) и наш числовой guard. Это диагностический корпус, не зелёная
приёмка. JSON фиксирует исходный текст и оба промежуточных этапа.

| Случай | Наблюдение |
| --- | --- |
| → и ⇒ | Hermes заменяет оба символа на `to` до внешней команды, теряя различие отношений |
| +7 (999) 123-45-67 | Hermes удаляет 123-45-67; восстановить номер в адаптере уже нельзя |
| +49 151 23456789 | Наш guard ошибочно воспринимает группы как количественные числа |
| Документ № 00123456789012345678 | В этом случае все цифры и начальные нули сохранены словами |
| 03.10.2026 | В этом случае правильно развёрнута русская дата |
| 2026-10-03. | Hermes удаляет дату; проверен вариант с точкой в конце предложения |
| 20°C / 45% | Hermes вставляет degrees Celsius / percent |
| Whisper, ElevenLabs, API | Написание сохранено; правильное произношение/входящее STT этим не доказаны |

Места: gateway/platforms/base.py prepare_tts_text и _synthesize_auto_tts;
tools/tts_tool.py text_to_speech_tool; tools/tts_text_normalize.py
normalize_symbols_for_tts / prune_identifier_tokens_for_tts; собственный
vendor/ru_numbers.py. Командный TTS и обычный TTSProvider получают уже очищенный
текст. Замена to на «затем» не восстанавливает ни исходный смысл, ни удалённые числа.

## Направление исправления

Готовить речь из исходного ответа до потерь. Детерминированно выделять телефоны,
идентификаторы с ведущими нулями, даты и величины. Различать цифры идентификатора
и количество, проверять календарные даты. Контекстные связи и иностранные термины
обрабатывать отдельным речевым сценарием; неизвестную причинность не додумывать.
При модельном переписывании проверять сохранение чисел, единиц, отрицаний и
терминов; механическая проверка не доказывает семантическую эквивалентность.

Проверен штатный transform_llm_output (agent/turn_finalizer.py): доступен исходный
response_text и идентификаторы сессии/хода, но возвращённая строка меняет и текст,
и историю. Это кандидат на простой общий ответ обычной прозой, НЕ отдельный
речевой канал. Для сохранения богатого текста и отдельного речевого сценария
нужно проверить собственный инструмент/доставку с точным origin либо ранее
начатый внешний Runs маршрут. Такое подключение ещё не реализовано/не проверено.
Чужое ядро и работающий профиль не изменены. Уточнение, относятся ли иностранные
слова к STT или TTS, запрошено; до ответа обе причины остаются возможными.
