# Названия и анимированные иконки тем Грейфа — 03.10.2026

Отдельный плагин automation-topic-style, без изменения Hermes и речевого плагина.
По запросу Дмитрия реализован автоматический выбор оформления по смыслу разговора.
Уточнение «автоматически или кнопками» запрошено; ответа не было, выбран обозначенный
по умолчанию автоматический режим. Кнопок выбора в этой версии нет.

## Поведение

Штатный pre_llm_call сохраняет задачу в собственную SQLite и немедленно возвращается.
Отдельный последовательный worker вызывает основную модель текущего профиля и
выполняет один editForumTopic с названием и icon_custom_emoji_id. Он не принимает
решения об адресе от модели, не получает Telegram updates и не отправляет сообщений.
Фиксированный бот100002 (@example_integration_bot), пользователь/личный чат100001.

Маршрут берётся только из bound ContextVars текущего вызова, session_id сверяется
с hook; глобальные env fallbacks запрещены. Чужой sender/chat, подагенты, отсутствие
thread, General и явно объявленные в dm_topics фиксированные темы пропускаются.
Native тест проверяет это, включая ложный chat_id в тексте пользователя и env.

Модель получает вопрос, последние четыре user/assistant сообщения, текущее оформление
и доступные emoji. Возвращает короткое название и иконку либо change=false. Короткие
отступления/благодарности не должны менять основную тему; пустой смысл допускает отказ.
Ограничение стабильности: не более одной подтверждённой смены за300сек. Пропущенные
в cooldown запросы не отложены на таймер: следующая оценка — следующее сообщение.
При новом запросе во время подготовки старое предложение отбрасывается.

## Правило трёх тем

Сравниваются разные темы одного чата, упорядоченные по числовому Telegram thread_id
(практический порядок создания), а не последние операции изменения и не изменяемый
порядок списка в клиенте. При новой теме исключаются иконки трёх предыдущих; при
изменении старой — также трёх следующих, чтобы не нарушить их окно предыдущих соседей.
Запрет применяется и по emoji, и по custom_emoji_id ДО модельного вызова и ПОСЛЕ ответа.

Гарантия относится к темам, наблюдаемым/оформленным этим плагином. Bot API не даёт
этому коннектору полного каталога прежних тем с текущими значками. Исходные неизвестные
иконки существующих тем не выдумываются; массовой миграции не было. Ручные изменения
значков за пределами плагина пока не наблюдаются, поэтому после них история может
устареть. Не заявлять глобальную синхронизацию всех старых и вручную оформленных тем.

## Telegram и модель

Официальные методы: [getForumTopicIconStickers](https://core.telegram.org/bots/api#getforumtopiciconstickers)
и [editForumTopic](https://core.telegram.org/bots/api#editforumtopic).
С живого Bot API прочитан каталог112стикеров, все с is_animated=true, без визуально
дублирующих emoji в этом снимке. Каталог перечитывается при первом задании worker.
Анимацию отображает клиент Telegram согласно его настройкам.

Прогон основной модели (4 вызова, БЕЗ изменения Telegram):

| Тема | Иконка |
| --- | --- |
| Монтаж электрощита и подбор автоматов | ⚡️ |
| Электропроводка и розетки в квартире | 💡 |
| Ремонт освещения и выключателей | 🏠 |
| Диагностика короткого замыкания | 🔎 |

Данные: `~/.local/share/automation-integrations/greif/topics/catalog.json`,
`smoke-report.json`. В тесте проверены четыре сходных темы, а не только четыре
заведомо разных предметных области. Это проверка выбора, не подтверждение живого edit.

## Размещение, состояние, отказ

- Код automation_integrations/topic_style.py; native binding bridges/hermes_topics.
- Установлено `~/.hermes/plugins/automation-topic-style`, standalone модуль скопирован
  туда при deployment; исходник канонический в automation-integrations.
- Приватное состояние `~/.local/share/automation-integrations/greif/topics/state/topics.sqlite3`.
  Оформление хранится отдельно от jobs. Контекст очищается после обработки; завершённые
  известные jobs удаляются после30дней при следующем enqueue. Это не фоновое стирание.
- Один worker защищён flock. prehook не ждёт модель/Telegram. Вызов основной модели
  использует нынешний профиль и его авторизацию; новые ключи не создавались.
- sending фиксируется до API; сбой/неподтверждённый ответ → outcome_unknown. Следующие
  изменения чата блокируются для ручной сверки, автоматических повторов edit нет.
  Незавершённые preparing при рестарте failed, sending → outcome_unknown.
- Ошибки модели/неверный emoji → failed, никаких произвольных «резервных» иконок.
- Нативное автоименование отключено через platforms.telegram.extra.disable_topic_auto_rename=true,
  чтобы два владельца не спорили за название. Фактический GatewayConfig подтвердил флаг.
  Сессии всё ещё могут иметь внутренние названия Hermes, не синхронизированные с внешним.

## Откат

```bash
cd /home/operator/workspaces/automation-integrations
python3 ops/greif_topics_config.py rollback
sudo systemctl restart hermes-gateway.service
```

Проверить отсутствие активных задач перед restart. Backup topics/backup/config.yaml,
manifest с хешем; если config менялся после включения, согласовать только plugins и
platforms.telegram.extra.disable_topic_auto_rename вручную. Откат отключает плагин и
восстанавливает прежний флаг автоименования. Уже изменённые названия/иконки сам по себе
не возвращает; последующее ручное восстановление сверять с jobs. Прежние неизвестные
имена до первого собственного оформления не сохранены. Откат речиphase2 теперь
требует сначала отключить тему-плагин или вручную согласовать изменённый config.

Резервная копия bridge до исправления: topics/backup/bridge-before-scope-fix.py.
Возврат только этого файла возвращает известный дефект; для отключения использовать rollback выше.
