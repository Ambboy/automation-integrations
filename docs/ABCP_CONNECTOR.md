# ABCP: внешний коннектор для Hermes

Коннектор использует штатный внешний плагин `automation-api-catalog`, отдельные
исполнители чтения и записи и собственное хранилище состояния. Исходники Hermes
изменять не требуется. Это публичный пример: учётные данные, идентификатор
владельца и настройки магазина необходимо задать в своей среде.

## Покрытие API

Контракт включает 287 документированных методов: 45 ABCP client, 76 ABCP admin,
30 TS client, 122 TS admin, 8 VINQU и 6 CarCare. Классификация содержит 135 чтений
и 152 операции с изменениями. Поддержаны PHP-вложенные form-параметры, CSV-списки,
JSON, multipart, параметры пути, авторизация отдельных семейств и бинарные ответы.

Источники — [официальная документация](https://www.abcp.ru/d/docs/api/public-api),
её сохранённые снимки и SHA256 в [abcp-api-research](abcp-api-research/README.txt).
Исполняемый контракт находится в `registry/contracts/abcp.json`, каталог методов —
в `registry/capabilities/abcp.json`. Документированное покрытие не подтверждает
права конкретного аккаунта или успешность бизнес-операций.

Для основного API и TS используются доступы ABCP; VINQU и CarCare требуют
отдельных значений. При их отсутствии возвращается
`credentials_not_configured_<family>`. Версию заказов определяет `/orders/version`;
выбор методов и административные права нужно проверить на своей учётной записи.

## Инструменты агента

- `integration_catalog`: `service="abcp"`, `view="capabilities"`, поиск по задаче
  или пути, страницы `offset/limit`. Точный `capability_id` раскрывает параметры;
  поле `adapter` задаёт `operation` для исполнителя.
- `integration_read`: документированные чтения, включая POST-чтения.
  `connection_status` проверяет наличие доступов локально; `result_page` выдаёт
  сохранённые большие ответы по частям.
- `integration_write`: `prepare → подтверждение владельца → execute → status`.
  При стандартной политике подтверждение принимается только новым сообщением
  `ПОДТВЕРЖДАЮ <UUID>` через аутентифицированный native hook.

Пример локальной проверки конфигурации:

```json
{"service":"abcp","operation":"connection_status","params":{}}
```

Пример проверки версии заказов через API:

```json
{"service":"abcp","operation":"abcp_client_get_orders_version","params":{}}
```

Для поиска запчасти сначала вызывается `abcp_client_get_search_brands` с `number`,
затем `abcp_client_get_search_articles` с точными `number/brand`. Онлайн-склады и
профиль цены выбираются по документированным параметрам и настройкам магазина.
Все страницы выборки нужно читать до указанного API `total/count`; конкретные
параметры пагинации зависят от метода.

Доступ ограничен личным Telegram-чатом настроенного владельца. Проверки выполняются
при каждом вызове; иной пользователь, группа, дочерний или непривязанный контекст
не допускаются. Произвольный URL, подмена авторизации и HTTP redirects запрещены.

## Установка

Требуются Python 3.11+, Linux и установленный Hermes с поддержкой native plugins.
Транспорт использует стандартную библиотеку Python. Установщику нужен PyYAML;
исследовательским скриптам — `requests` и `beautifulsoup4` только при пересборке
документации. Код самого Hermes и его зависимости менять не требуется.

1. В `ops/abcp_release.py` и `ops/abcp_native_probe.py` замените демонстрационный
   `OWNER = '999000111'` на Telegram ID владельца. Название агента и подписи
   магазина при необходимости настройте в `ops/abcp_build_release.py`.
2. Соберите новый пустой каталог bundle из корня репозитория:

   ```bash
   python3 ops/abcp_build_release.py /absolute/new/abcp-bundle
   ```

3. На машине Hermes подготовьте приватный каталог
   `~/.local/share/automation-integrations/abcp/`. Файл `credentials.env` должен
   содержать выданные провайдером значения, по одному `KEY=value` на строку:

   ```text
   ABCP_API_HOST=shop.public.api.abcp.ru
   ABCP_API_LOGIN=<api-login>
   ABCP_API_PASSWORD_MD5=<provider-password-md5>
   ```

   Для отдельных сервисов при наличии доступа добавляются `VINQU_SITE_HASH`,
   `VINQU_ACCESS_HASH`, `CARCARE_SITE_LOGIN`, `CARCARE_SITE_PASSWORD_MD5`.

4. Создайте рядом `config.json`, подставив абсолютные пути своей среды:

   ```json
   {
     "credentials_file": "/home/operator/.local/share/automation-integrations/abcp/credentials.env",
     "state_dir": "/home/operator/.local/share/automation-integrations/abcp/state",
     "timeout_seconds": 45,
     "write_policy": "explicit_confirmation"
   }
   ```

   Каталог должен иметь права `0700`, оба приватных файла — `0600`.
   Credentials, config и накопленное состояние хранятся вне bundle и Git.

5. Передайте bundle на машину Hermes. Выполните подготовку с новым путём backup:

   ```bash
   python3 /absolute/abcp-bundle/ops/abcp_release.py prepare \
     --source /absolute/abcp-bundle \
     --backup /absolute/private/abcp-backup
   ```

6. Проверьте отсутствие активных задач, штатно остановите gateway, выполните
   `apply` с теми же `--source` и `--backup`, затем запустите gateway. При иных
   каталогах Hermes/runtime задайте одинаковые `--home` и `--root` на каждом шаге.
   Установщик сам не останавливает и не перезапускает службы.

Установщик проверяет SHA перед записью, сохраняет исходное состояние и откатывает
свои изменения при ошибке. Он откажется заменять уже настроенный чужой экземпляр
`automation-api-catalog`; установку нескольких каталогов в одном профиле нужно
проектировать отдельно. Прочие расширения Hermes сохраняются.

## Запись и неизвестный результат

Предпросмотр содержит точные параметры, скрывает пароли и заменяет содержимое
файлов размером и SHA256. Черновики привязаны к аккаунту, контракту, параметрам и
исходному scope. Файловая блокировка сериализует отправки; `submitting` сохраняется
и fsync завершается до обращения к API. Неизвестный результат после timeout/crash
не повторяется; создание нового UUID не обходит блокировку дубликата намерения.

`accepted_unverified` означает ответ провайдера, а не бизнес-завершение. После
записи нужны документированные чтения возвращённых ID. Частичный успех сохраняет
полученные объекты; `status=0` с созданными заказами не считается полным отказом.
Для отправки поставщику отрицательный `confirmSend` не доказывает отсутствие заказа:
неоднозначные ответы требуют сверки фактического состояния.

Универсальной автоматической сверки всех сущностей нет. Повтор намеренно
идентичного действия требует операторской проверки и архивирования точного старого
черновика под `state/abcp-writes/workflow.lock`. Неопределённую отправку нельзя
удалять или произвольно менять её статус.

Политика `owner_command` поддерживается кодом, но стандартная установка использует
`explicit_confirmation`. Изменение политики — отдельная настройка владельца.
Автоматических повторов API-запросов или фоновой синхронизации нет.

Большие ответы сохраняются целиком и возвращают `result_id`, JSON Pointer и
`next_offset`; бинарные файлы находятся в приватном каталоге результатов.
Вход ограничен 2 MiB, ответ API — 32 MiB, настраиваемый timeout — от 1 до 90 секунд.

## Проверка

Проверки контрактов и модульные тесты выполняются без реальных бизнес-операций:

```bash
python3 docs/abcp-api-research/verify_catalog.py
python3 -m unittest discover -s tests -p 'test_abcp*.py' -v
python3 -m unittest tests.test_api_catalog tests.test_yandex_workflow -v
```

Опциональный тест native bridge требует установленного Hermes и
`HERMES_NATIVE_TEST=1`. `ops/abcp_native_probe.py --output /absolute/private/probe.json`
предназначен для запуска через установленный runtime/bootstrap Hermes: он проверяет
плагин и делает два реальных чтения API. Бизнес-запись, модель и отправка Telegram
не запускаются. Непустой поиск тестового артикула зависит от настроек магазина.

Публичные тесты подтверждают программные контракты. Квитанции аккаунта и результаты
проверок эксплуатационной среды в репозитории не публикуются.

## Отключение и откат

Для отключения удалите только `automation-api-catalog` из `plugins.enabled` и
`automation-api` из Telegram toolsets; штатно перезапустите Hermes после завершения
задач. Credentials, документы и накопленные результаты сохраняются.

Для точного отката остановите gateway и выполните `rollback` с теми же
`--source`, `--backup`, `--home` и `--root`, что при установке, затем запустите gateway.
Если текущие файлы изменились после установки, установщик откажется их перетирать:
проверьте diff и сохраните последующие изменения. Credentials и состояние не удаляются.
