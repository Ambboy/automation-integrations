# Контракт v1

## Границы

Программа подключается своим адаптером. Адаптер переводит доверенные события программы в JSON; сервис проверяет scope, сохраняет задания и запускает обработчики. Транспорт отправляет результат. События не передают Python-объекты программы, токены мессенджеров, исполняемые команды или имена импортируемых модулей.

Модули работают в одном доверенном процессе, это не sandbox для произвольного стороннего кода. Токен подключения даёт право утверждать происхождение события в пределах его allowlist; сервис не может самостоятельно доказать, что произвольный клиент действительно получил событие от Hermes. Мост должен получать идентичность из подтверждённого контракта хоста, никогда из текста ответа модели.

## HTTP

Только `127.0.0.1`. Для межсерверного подключения требуется отдельно спроектированный защищённый транспорт; публичный listener v1 запрещён.

| Метод | Путь | Результат |
|---|---|---|
| GET | `/health` | Минимальный readiness: жив ли worker, без сведений подключений |
| POST | `/v1/events` | `202 {job_id, created:true}` только после commit; повтор — `200 ...false`; конфликт — `409` |
| GET | `/v1/jobs/{id}` | Состояние, подтверждения частей и журнал, только своего подключения |
| GET | `/v1/status` | Режим и счётчики только своего подключения |

Кроме `/health`, обязателен `Authorization: Bearer …`. Секрет читается из owner-only файла; не передаётся в URL или логи. Токен кешируется до перезапуска сервиса. Event body ≤128 KiB. Профиль, платформа, чат, пользователь и темы задаются оператором в конфигурации. `thread_ids:["*"]` — явное разрешение всех тем только этого чата и пользователя; остальные поля не поддерживают wildcard.

```json
{
  "schema": 1,
  "event_id": "stable-producer-event-id",
  "kind": "reply.completed",
  "occurred_at": "2026-10-03T12:00:00+00:00",
  "source": {
    "profile": "server", "platform": "telegram", "chat_id": "123",
    "thread_id": "7", "user_id": "456", "message_id": "10",
    "session_id": "session-id", "turn_id": "turn-id"
  },
  "data": {"text": "Ответ для произнесения", "origin_type": "voice"}
}
```

`topic.observed` использует тот же source и `data:{"title":"Текст темы для классификации"}`. Непустой thread обязателен. Это подсказка для выбора значка, не команда переименования. Мост v0.1 может использовать первые 128 символов первого входящего запроса; он не утверждает, что наблюдает сгенерированное Hermes название.

Строковые ID имеют ограниченные длину/алфавит. Ответ ≤24 000 символов; нормализатор голоса v0.1 принимает ≤8 000 после удаления кода, think-блоков и URL. Слишком длинный/неподдерживаемый текст завершается явной ошибкой задания. TTL по умолчанию 24 часа (настраивается до 7 дней); допустимое опережение часов 60 секунд. Разрешения и TTL повторно проверяются перед обработкой.

## Доставка и состояние

Одинаковые `(connection,event_id)` и payload создают одно задание. Другой payload с тем же ключом — конфликт. Потеря ответа HTTP безопасна для повторной передачи неизменённого события. При повторе нельзя генерировать новый ID или timestamp.

Задание: `queued → running → delivered | simulated | failed | partial | outcome_unknown | superseded`.

Каждое исходящее действие сохраняется до отправки: `prepared → sending → delivered | failed | outcome_unknown`. Результат сохраняется вместе с квитанцией; журнал не содержит текста сообщений. Несколько частей голоса имеют отдельные действия. `partial` означает подтверждённые части и остановку до завершения остальных, `outcome_unknown` — хотя бы одну потенциально выполненную отправку без подтверждения.

При перезапуске:

- `queued` продолжает ожидать;
- незавершённая подготовка становится `failed`, чтобы не повторять возможный платный TTS;
- `sending` становится `outcome_unknown`;
- полностью подтверждённый набор действий остаётся `delivered`;
- частично подтверждённый набор не проигрывается заново.

Автоматического retry исходящих запросов нет, включая 429. Operator retry требует отдельного решения по квитанциям; такой управляющий API намеренно не реализован в v0.1. Гарантия exactly-once со стороны Telegram не заявляется: commit и внешний API не образуют общую транзакцию.

Dry-run закрепляется в задании при приёме. Включение реальной отправки не активирует старые тестовые задания. Глобальный dry-run дополнительно блокирует транспорт для любых заданий. Симуляция каталога значков ограничена нейтральными вариантами и не является проверкой доступности конкретного emoji в Telegram.

Для значков хранится версия по timestamp источника и scope. Более старое событие, пришедшее позже, не заменяет новое. Смена значка и его запись в историю подтверждаются квитанцией. Проверка свежести происходит непосредственно перед запросом; Telegram не поддерживает наш CAS, поэтому при приходе нового события во время запроса возможна краткая промежуточная иконка до следующего задания. Ручные изменения за пределами сервиса он не наблюдает: v1 можно назначать только темы, оформлением которых управляет он один.

## Голосовой провайдер

Команда задаётся оператором как массив argv с абсолютным executable и `{output_file}`; shell не используется. Нормализованный текст приходит в stdin, результат — WAV. Команду/аргументы пользовательский event выбрать не может. Секреты провайдера принадлежат его собственному окружению/защищённой конфигурации; в JSON-примерах ключей нет.

Проверка чисел запускается в отдельном процессе с лимитом 5 секунд; TTS и обработка медиа также ограничены временем, при timeout убивается группа процесса. FFmpeg создаёт Ogg/Opus по 55 секунд, FFprobe независимо проверяет кодек и фактический предел 60 секунд. Не прошедший проверку файл не отправляется. Максимум 30 частей, WAV ≤128 MiB, отдельная отправляемая часть ≤8 MiB.

Нет LLM-перефразирования, обещания полной смысловой эквивалентности или проверки произношения провайдера. Исходный текст Hermes не редактируется. Простые указания «только текстом», «без голос…», «не озвуч…» подавляют дополнительный голос; предпочтение сохраняется для подтверждённых внутренних продолжений. Продолжение без сохранённого исходного предпочтения не озвучивается. Это ограниченный набор правил v0.1.

## Добавление модуля

1. Класс с `name`, `version`, `event_kind`, методом `plan(event, context) → list[action]`.
2. Явная регистрация в `MODULES`, контракт входного события в `contracts.py`, allowlist модуля в конфигурации.
3. Побочные действия — только через transport worker. Обработчик не отправляет сообщения и не читает БД Hermes.
4. Новое действие добавляется в транспорт с явным подтверждением результата и проверками отказов.
5. Контрактный тест, конфигурация, описание требований и совместимости.

Пока это небольшой явный реестр для двух собственных модулей, а не marketplace или универсальная загрузка недоверенного кода. Встроенные hooks Hermes остаются адаптерным слоем; очередь Hermes `emit/subscribe` не используется для надёжной доставки.
