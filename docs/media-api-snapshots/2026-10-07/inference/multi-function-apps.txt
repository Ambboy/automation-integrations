Expose multiple entry points from a single app to share resources and reduce cold starts.
Why Multi-Function?
Instead of deploying separate apps for related operations, multi-function apps let you:
Share model loading — Load heavy models once, use across functions
Reduce cold starts — Warm workers serve any function immediately
Logical grouping — Keep related operations together
Example use cases:
Image models: generate, upscale, inpaint
LLMs: chat (history-aware) vs completion (raw text)
Data pipelines: process, validate, export
Function Discovery
Functions are automatically discovered from public methods on your App class.
Discovery Rules
Python
A method becomes a function if it meets all these criteria:
| Rule | Description
| Public | Name doesn't start with _
| Not reserved | Not setup or unload (lifecycle methods)
| Has type hints | Both input parameter and return type annotated
| Pydantic models | Input/output types are Pydantic models
| Single parameter | Exactly one parameter (besides self)
Node.js
A method becomes a function if:
| Rule | Description
| Public | Name doesn't start with _
| Not reserved | Not setup, unload, onCancel, constructor
| Has schema exports | {PascalName}Input and {PascalName}Output Zod schemas exported

Default Function
If no function is specified, resolution order is:
Explicit default_function in inf.yml (if set)
A function named run (if present)
The sole function (when the app has exactly one entry point)
Otherwise, an error — use -f / --function to pick one
belt app get and belt app sample list other functions with descriptions and copy-pasteable belt app run / belt app sample commands when an app has multiple entry points.
