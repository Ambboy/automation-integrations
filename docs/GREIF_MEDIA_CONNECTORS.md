# fal.ai и inference.sh в каталоге Грайфа

Канонические исходники: `/home/operator/workspaces/automation-integrations`.
Штатный плагин Hermes: `automation-api-catalog` 0.8.0. Код Hermes не изменяется.
Состояние, jobs, budgets, ответы и файлы: `api-catalog/state/media` в существующем
private runtime. Ключи получает отдельный runner из действующего Vaultwarden;
в реестре и этом документе ключей нет.

## Возможности и полнота

Сначала проверены существующие ключи, затем сохранены официальные спецификации,
REST-документация и сведения SDK. Источники с URL/датой/SHA находятся в
`docs/media-api-snapshots/{fal,inference}`. Описание конкретных ограничений:
[FAL_CONNECTOR.md](FAL_CONNECTOR.md) и [inference-connector.md](inference-connector.md).

Для fal инвентаризированы 88 Platform API операций плюс динамическое исполнение
моделей, очереди, статусы, результаты, отмена, SSE и загрузка файлов. Для
inference инвентаризированы все 714 методов опубликованного OpenAPI; 233 операции
реализованы провайдерным модулем. Включены приложения, версии и функции, задачи,
files, flows, agents, sessions, MCP, usage/billing и документированные операции
управления. Внутренние, административные и неподдержанные методы не объявляются
проверенными только из-за наличия в спецификации.

Фиксированного списка моделей нет: живые `model_schema` / `app_get_by_ref` дают
актуальные полные входные схемы. Новая модель не требует нового инструмента.
Общая карточка содержит именованные операции; `operation_schema` и точный
`capability_id` возвращают подробные параметры. Большие ответы сохраняются
полностью и читаются через `response_read` с JSON pointer, offset и chunk_chars.

Реально исполняемые карточки с локальными операциями: fal — 72 чтения / 42 записи;
inference — 166 чтений / 75 записей. Эти числа включают удобные алиасы и локальные
операции и не равны количеству уникальных HTTP routes. Реестры генерируются
`python3 -m ops.build_media_catalog`; после обновления provider contracts этот
шаг нужно повторять. `schema`/`params_schema` выдаются полностью при точном
запросе, но не размножаются в каждой странице краткого перечня.

## Работа Грайфа

1. Найти сервис и модель через `integration_catalog` / `integration_read`.
2. Прочитать входную схему, затем `integration_write prepare` с точным запросом.
3. Проверить preview и исполнить поручение владельца через `execute`. Отдельная
   UUID-фраза не требуется: применяется настроенная `owner_command` и доказанный
   штатным hook текущий личный Telegram-маршрут. Просьба только показать цену
   или возможности не разрешает генерацию. Администрирование, удаление,
   публикация, покупка ресурсов и расписания требуют поручения именно на них.
4. Для fal предпочитать `submit`, для inference — `app_run`. Ответ сохраняет
   собственный `job_id` и идентификатор провайдера; `job_status` / `job_result`
   продолжают задачу без повторного списания. После timeout/unknown нельзя
   повторять запуск или заменять его новым сообщением с теми же параметрами.
5. `artifact_download` скачивает результат и возвращает путь, MIME, размер и SHA.
   Грайф отправляет его существующим инструментом доставки медиа в исходный
   диалог. Сам коннектор не запускает автономную Telegram-рассылку.

`upload_file` принимает путь из разрешённых каталогов вложений/файлов; размер
до 8 MiB для fal и 32 MiB для inference. Подготовка фиксирует stat/SHA, исполнение
проверяет неизменность. Бинарные данные не проходят через аргументы модели.
Вернувшийся `artifact_id` можно передать в следующем входе как
`artifact:<id>` либо `{ "artifact_id": "<id>" }`: подписанный URL разрешается
внутри runner с проверкой аккаунта. Публичные IP/DNS pinning, запрет redirects,
проверка MIME/размера и отсутствие API credentials на CDN сохранены.

## Деньги и доступ

В inference баланс возвращается в microcents: **1 USD = 100 000 000**. Значения баланса и стоимость конкретного запуска сохраняются только в локальном отчёте.
Итоговый расход берётся из `charged - refunded` через task cost. Временная ошибка
чтения стоимости не запускает генерацию повторно: следующее чтение повторяет
только сверку стоимости.

Действующий FAL_KEY читает каталог/схемы/цены. Запуск генерации отклонён HTTP 403:
провайдер явно сообщил `Exhausted balance`. Это подтверждённое исчерпание средств,
а не предположение по одному HTTP-коду. Теперь такой ответ классифицируется
`insufficient_credits`. Точный баланс через billing API недоступен текущему
ключу: нужен отдельный ADMIN credential, для которого предусмотрен
`fal_admin_item_id`; он не является обязательным для обычной генерации.

Числовые дополнительные лимиты владельцем пока не заданы. Политика
`media_limits.<service>.per_task/day/month` поддерживается, но значения не
выдумывались. Пустая политика не ограничивает расходы дополнительным локальным
потолком. При настроенном ограничении неизвестная или историческая цена не
считается верхней границей и запуск блокируется. Для `app@version` цена текущей
версии магазина не выдаётся за оценку закреплённой версии.

Ledger учитывает только вызовы через этот коннектор. Сторонние клиенты,
долгоживущие ресурсы и расписания провайдера могут расходовать средства вне него.
Автопополнение счетов не включалось. Оценка не заменяет фактическое списание;
неразрешённые неизвестные исходы сохраняют резерв.

## Проверки и выпуск

Финальный общий suite: **527 тестов прошли за 66.506 с** после всех исправлений.
Итоговый отчёт без ключей: MEDIA_CONNECTOR_VALIDATION.json (локальный отчёт; в публичную копию не входит).
Отдельно после дополнительной классификации FAL403 прошёл целевой набор
из 111 тестов с ResourceWarning-as-error.
Native hook/tools/dispatch проверены на установленном Python Hermes без
bootstrap; результат — `docs/MEDIA_NATIVE_UNIT_VALIDATION.json`. Проверены
личный маршрут, чужой пользователь, delegated context, новый ход и schemas.
Production launchers после native-теста побайтно сохранены.

Контрольный inference запрос прошёл prepare → submit → running → completed →
сверка стоимости → скачивание PNG. Дополнительно прошли signed file upload,
обратное скачивание и загрузка локального изображения. Для fal проверены
каталог, схема, цены, оценка, billing403 и окончательный отказ queue403 из-за
исчерпания средств; успешная генерация fal пока не подтверждена.

Live smoke использует явно синтетический контекст приёмки; это не входящее
Telegram-сообщение. Изображение пользователю не отправлялось. Полный сценарий
с реальным сообщением владельца и доставкой на его устройство отдельно не
наблюдался. Публичный webhook receiver и постоянные WebSocket-сессии не
реализованы; SDK/CLI-only deployment и выдача нового fal API secret требуют
отдельных исполнителей. Это отражено в capability inventory.

Установка: `python3 -m ops.greif_media_release prepare`, затем при свежем
`active_agents=0` и отсутствии выполняемой озвучки остановить **только**
`hermes-gateway.service`, выполнить `apply` и запустить gateway. Конфигурация
Hermes и прочие плагины защищены SHA; private.json меняется адресно — привязки
двух существующих ключей и owner-command policy. Замороженный выпуск и preimage:
`api-catalog/update-20261004-media/deployment`. Ранний исходный снимок — `baseline`.

Откат: при свободном gateway выполнить stop →
`python3 -m ops.greif_media_release rollback` → start. При поздних изменениях
CAS останавливает откат; не перезаписывать их. Jobs, результаты и provider
сущности при откате не удаляются. VPN, Vaultwarden и Hermes core не меняются.

Выпуск установлен:16 целей,32 защищённых файла; gateway PID439844,
invocation `e23e0a6b79074281ad06e2f5db36001d`, Telegram connected. В native
installed-проверке обнаружена и исправлена отдельная ошибка standalone-reader:
запуск api_read.py как __main__ порождал второй класс Failure при импорте
расширением, и HTTP403 превращался в local_execution_failed. Регрессия и
атомарный patch сохранены в `deployment/reader-fix`; основной rollback учитывает
его автоматически. Повторная installed-проверка прошла8/8 ожидаемых результатов,
включая штатный FAL billing403 и прежнее чтение Яндекс Go. Полные квитанции —
`update-20261004-media/installed-native.json`. Дополнительный рестарт не требовался.

Документация коннектора подключается через существующий каталог; публикация
групповой технической базы не выполняется.
