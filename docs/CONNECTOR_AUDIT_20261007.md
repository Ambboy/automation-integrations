# Аудит надёжности коннекторов — 07.10.2026

Публичное дополнение охватывает восемь коннекторов: Яндекс Go, ЭТМ, Saby,
Точка, Wiren Board, fal.ai, inference.sh и ABCP. Оно включает исправления
исполнителей, машинных контрактов и генераторов, регрессионные тесты и единый
индекс параметров. Рабочие конфигурации, ответы частных аккаунтов, квитанции
установки и результаты эксплуатации в этот отчёт не входят.

Цель проверки — согласовать документированный запрос, локальную валидацию,
передачу параметров и интерпретацию результата. Наличие метода в документации,
наличие исполнителя и успешный бизнес-сценарий учитываются отдельно.

## Состав и изменения

| Коннектор | Область контракта | Исправление и граница применения |
|---|---|---|
| Яндекс Go Business | 52 документированных метода | Четыре записи получают сохранённый UUID черновика в обязательном `X-Idempotency-Token`. Распознаются ошибочные конверты при HTTP 200; неоднозначный контракт персональных лимитов остаётся недоступным. |
| ЭТМ iPRO | 19 методов публичной спецификации и специальные сценарии адаптера | Общая обработка транспортных сбоев и ответов применяется к существующему сценарию заказа. Сохраняются проверка региона, договора и цены, стабильный номер заявки, обработка разделённых документов и чтение результата. Это не новая приёмка оформления заказа. |
| Saby | 91 учтённый метод ЭДО и связанных справочников; 70 исполняемых RPC | Исправлены повреждённый кеш, ротация параметров авторизации, миграция старого токена и проверка RPC-ответа. 21 исключение явно описано в контракте; область не охватывает все отдельно лицензируемые продукты Saby. |

| Wiren Board | 72 метода OpenAPI; 10 облачных чтений, 11 облачных изменений и одна составная команда | Отсутствующие необязательные `next`/`previous` больше не ломают страницу: продолжение вычисляется по `count` и параметрам страницы. Прямой и SSH HTTP-транспорт отвергают неконечные JSON-числа. Остальные маршруты не становятся исполняемыми автоматически. |
| fal.ai | 89 платформенных методов из объединения опубликованных спецификаций | Добавлены актуальная сортировка каталога и `X-Fal-Request-Start-Timeout`. Исправлены проверка результата очереди и обработка ошибок. Статическая документация compute не подтверждает фактическую доступность ресурса. |
| inference.sh | 832 записи реестра; 235 проверенных контрактов | Исправлены асинхронные flow/chat, различение принятой и завершённой задачи, подписанные пути загрузки и сохранение ошибок. Остальные записи без достаточного контракта явно недоступны. |
| ABCP | 287 методов шести семейств API | Уточнены 58 контрактов: документированные пределы и ложная обязательность полей. Смешанный результат `basket/add` классифицируется как `partial`; исправлены обработка оборванного ответа и проверка JSON-экспорта. Статусы TS2 выбираются через собственные методы позиций. |

интерфейсных сценариев Saby используют шесть RPC: алиасы не увеличивают число
методов поставщика. Сумма строк таблицы не является
числом независимых реализованных бизнес-сценариев.

## Общие гарантии обработки

Транспорт распознаёт усечённый ответ, некорректный JSON, HTTP 429 и `Retry-After`.
Транспорт ABCP и Wiren Board также отвергает неконечные JSON-числа. Машинная ошибка не включает
исходный текст, который может содержать данные аккаунта. Неопределённый результат
записи сохраняется: он не разрешает автоматически повторить отправку, заказ или
платную генерацию. Частично исполненная корзина ABCP также не считается полным
отказом, после которого безопасно создать дубликат.

Диагностические квитанции записываются атомарно с синхронизацией каталога.
Повреждённая квитанция не отключает обнаружение всех сервисов, а запись другого
метода или сервиса не считается подтверждением текущей операции. Успешный
HTTP-ответ по-прежнему требует проверки формы ответа и бизнес-ошибок.

Saby использует общий механизм сессии для старых имён и скомпилированных RPC.
Кеш с fingerprint связан с параметрами приложения; валидный старый кеш без
fingerprint сохраняется без выдуманной привязки к текущим ключам. Чтение допускает
не более одного обновления после явного 401. Запись из-за ошибки сессии не
повторяется.

Для ABCP инструкция сначала предлагает `orders/version`. В TS2 строковый статус
читается через `/cp/ts/positions/list` или `/cp/ts/positions/get`: у списка фильтр
`statuses` — массив, у `/cp/ts/orders/list` фильтр `positionStatuses` — строка через
запятую. Справочники `orders/statuses` и `cp/statuses` семейства ABCP1 не подменяют
этот сценарий. Состояние заказа оценивается по всем его позициям с пагинацией.

## Параметры и источники

[Сводный реестр](connector-audit/2026-10-07/README.md) и
[машинный индекс](connector-audit/2026-10-07/parameter-index.json) генерируются из
`registry/catalog.json`, `registry/capabilities/`, `registry/contracts/` и
описаний локальных валидаторов. Индекс содержит путь, метод, вложенные параметры,
обязательные поля, enum, ограничения, источники и доступность исполнителя.
`schema_coverage`, `unsupported_reason` и `validator_sources` показывают границы
схемы и место дополнительной проверки. Неописанные поставщиком ограничения не
дополняются предположениями.

Генерация индекса не скачивает новую документацию и не проверяет права аккаунта.
Числа чтений и записей в нём включают совместимые имена и локальные операции;
для отдельного ABCP-плагина доступность отражается отдельно от основного каталога.
Индекс сохраняет SHA256 исходных контрактов, поэтому изменение параметров можно
сопоставить с конкретной версией реестра.

## Воспроизведение и ограничения

Из корня публичной рабочей копии, Python 3.11+:

```bash
python3 -m unittest discover -q
python3 docs/abcp-api-research/verify_catalog.py
python3 -m ops.connector_audit --output docs/connector-audit/2026-10-07
```

Последняя команда пересоздаёт два файла индекса и возвращает ненулевой код при
обнаруженных несогласованностях. Она проверяет уникальность capability ID и
соответствие имён чтений основного каталога runtime; это ограниченная проверка
согласованности, а не полная формальная проверка всех схем.
Результаты прогона именно публичной ревизии фиксируются в
[PUBLICATION.md](../PUBLICATION.md). Приватные проверки установленного окружения
не используются как результат публичного тестового набора. Native opt-in требует
отдельного Hermes runtime; его пропуск в обычном запуске виден в отчёте тестов.
Медиа-тесты с кодированием требуют `ffmpeg` и `ffprobe`.

В этой публичной ревизии выполнены 802 теста: 801 успешен, один native opt-in
пропущен. Сводный индекс восьми сервисов собран без ошибок. При сборке индекса
fal используется полная схема операции, включая обязательное тело запроса;
список OpenAPI-параметров заголовка/пути не заменяет эту схему.

Для отдельной проверки установленного окружения предусмотрен
`ops/connector_live_smoke.py`: 15 фиксированных чтений семи сервисов через
изолированный native-контекст Hermes. Скрипт требует `--execute`, установленный
Hermes runtime и его настроенные подключения. При включении ЭТМ обязателен
`--etm-product-id` с существующим товаром из каталога; примерное значение в коде
не используется для живого запроса. Состав и параметры доступны через `--help`.
Дополнительные локальные portal-операции, отсутствующие в публичном контракте,
в этот набор не включены. ABCP проверяется отдельным инструментом его плагина.
В ходе подготовки этой публикации живые запросы не выполнялись.

Тесты используют локальные состояния и имитаторы. Они проверяют повторную
отправку, сбои JSON/HTTP, пагинацию, частичные результаты, кеш сессии, заголовки,
схемы и жизненный цикл задач. Они не доказывают доступ к конкретному продукту,
лицензию, баланс, работоспособность модели или завершённую оплату, поездку,
закупку, подпись и доставку.

VINQU и CarCare требуют собственных доступов; права облака и устройств Wiren Board
проверяются отдельно. WebSocket, постоянные SSE-соединения, приём webhook и часть
SDK-only операций медиа остаются ограниченными согласно capabilities. Пагинация
сохраняет указатели продолжения и не выдаёт одну страницу за всю выборку.
Оценка стоимости не является гарантированной ценой. Для эксплуатационной приёмки
нужен отдельный сценарий с известными правами, ожидаемым бизнес-результатом и
проверкой этого результата чтением.
