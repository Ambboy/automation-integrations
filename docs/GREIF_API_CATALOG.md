## Устройство и границы

- Канонический реестр без секретов: `registry/catalog.json`. Runtime использует
  неизменяемую на этом этапе установленную копию; редактирование git-файла само
  по себе не обновляет production. Изменения выпускаются после проверок.
- `automation_integrations/catalog.py`: индекс, поиск по названиям/задачам,
  полные карточки с параметрами, ограничениями и квитанциями конкретных проверок.
- `bridges/hermes_catalog`: штатные `pre_llm_call`, `register_tool`, `on_unload`.
  Контекст подставляется перед каждым ходом. На установленной базе Hermes
  hook вызывается после turn-start compaction; внутри хода ephemeral context
  сохраняется механизмом Hermes. Полная принудительная compaction модели
  в этом этапе не воспроизводилась.
- `integration_catalog`: найти существующий путь; `integration_read`: выполнить
  одну из 16 разрешённых операций чтения. Произвольных HTTP методов, URL, shell
  или Saby RPC методов в аргументах нет.
- Разрешён только личный Telegram-маршрут владельца, проверенный через связанные
  ContextVars текущего профиля/сессии и sender hook. Процессные env-подстановки,
  другой чат, чужой пользователь, другая сессия и дочерний агент доступ не получают.
  Для tools admission хранится по session с TTL 1 час: pre_llm hook исполняется
  в отдельном bounded worker, его записи ContextVar не возвращаются агенту.
- Ядро Hermes не менялось. Не добавлены poller, фоновый мониторинг или внешние
  сообщения. Речь и оформление тем сохранены.

## Исполнение и секреты

`automation_integrations/api_read.py` запускается отдельным stdlib процессом.
Настройки с opaque ID записей — private.json; значения извлекаются по точному ID
через текущий Bitwarden CLI и сеанс Vaultwarden. В исполнитель выбираются только
поля соответствующего сервиса; модель не получает токены. Bitwarden физически
возвращает целую выбранную запись, поэтому общая hermes-env по-прежнему шире
одного сервиса в памяти resolver. Реструктуризация хранилища не выполнялась.

Токены не передаются в argv; stderr провайдеров и сырые ошибки/URL не возвращаются.
HTTPS проверяется, redirects запрещены, окружение proxy не наследуется. Для Точки
закреплён SHA-256 ранее проверенного официального корневого сертификата. Saby
кеширует токен под flock, renew только один раз при HTTP 401. Его кеш — локальный
runtime-секрет 0600, а не новая каноническая запись. Другие токены не сохраняются.

Ответ ограничен 2 МиБ на входе и 60 КБ после очистки; при превышении возвращается
ошибка с предложением уменьшить страницу. Ссылки на файлы и чувствительные поля
скрываются рекурсивно; известные секреты также удаляются из строк. Данные документов
остаются недоверенным содержимым. Квитанции содержат только service/operation,
время, ok и безопасный код ошибки; в них нет параметров и содержимого ответа.

Это граница новых инструментов, **не изоляция всего Грейфа**: ранее выданный
владельцу широкий terminal/vaultctl доступ не отозван. Каталог направляет модель,
но не блокирует все возможные обходы через другие инструменты.

Прямое соединение с публичной документацией ЭТМ также завершилось timeout.
Существующий маршрут до Алёны рассмотрен read-only: SSH keyscan через GRE и
публичный адрес не получил ключ сервера; SSH-личность не подтверждена, ключ из
Vaultwarden не материализован. Правила сети/VPN/firewall не менялись. Восстановление
российского выхода ЭТМ — оставшийся эксплуатационный шаг; не объяснять этот отказ
неверным паролем или отсутствием API. Запись о неудаче доступна модели в карточке.

Остальные девять операций не проверены живыми запросами; unit fixtures не подменяют
их live-приёмку. Выборка Saby одного типа/страницы не является полным архивом ЭДО.
Список ранее подготовленных банковских выписок не доказывает отсутствие платежей.
Платежи, подпись/отправка ЭДО, создание/отмена поездок, оформление заказов ЭТМ и
создание новых выписок пока не реализованы этим инструментом.

67 unit tests passed, включая прежние речевые/тематические тесты. Native test:
настоящий PluginManager + tool definitions + hook + registry dispatch; новый ход
с пустой историей, поиск без бренда, scope denial, copied-context worker и unload.
Четыре настоящих модельных запроса с пустой историей выбрали integration_catalog
для всех четырёх сервисов при наличии альтернативного web_search. В этом стенде
исполнялся только поиск по реестру, бизнес-API и Telegram не вызывались; production
auth не изменилась. Это тест выбора инструмента, не полный Telegram E2E.

Первый модельный стенд не дошёл до модели из-за позднего импорта bootstrap при
смене временного home; исправлена ранняя активация существующего runtime. Новый
временный home первого стенда создал собственные managed-зависимости, рабочая
конфигурация/окружение gateway не переключались. Native-тест исправлен на
публичный get_plugin_manager: ручной второй manager конфликтовал с ленивой
загрузкой tool definitions. Код Hermes не исправлялся.

Дополнительно `ops/catalog_installed_smoke.py --execute` проверяет установленную
копию plugin → native tool dispatch → отдельный runner → реальный users Яндекс Go.
Проверка завершилась passed=true. Квитанция `installed-smoke.json` хранится в private root; это синтетический
аутентифицированный маршрут, не входящее сообщение Telegram.

## Установка и откат

Private root: `/home/operator/.local/share/automation-integrations/greif/api-catalog`.
Plugin: `/home/operator/.hermes/plugins/automation-api-catalog`.
Там же private root содержит `private.json`, `tochka-root.pem`, `state/`, `release/`,
`backup/`, `validation.json`, `model-report.json`, `installed-smoke.json`.

`ops/greif_catalog_config.py apply` сохраняет байтовую копию config, проверяет
конкурентные изменения и меняет только plugin settings/enabled и добавляет
`automation-api` в Telegram toolsets. Read-back подтвердил неизменность речи,
оформления тем и прочих секций. Gateway перезапущен при свежем active_agents=0.
До: PID130878 / InvocationID6591b89e4fe644559ba40e76eb2db12b.
После: PID151413 / InvocationIDa01956f7d88e42c0a8092a1286c80385, active,
Telegram connected; cache discovery содержит automation-api.

Откат: `python3 ops/greif_catalog_config.py rollback`, затем отдельный idle restart
system `hermes-gateway.service`. При изменённом SHA config rollback останавливается:
нужно сохранить последующие пользовательские правки. Откат возвращает config и
выносит каталог плагина из discovery в `disabled-plugin` под private root. Одного
удаления из enabled недостаточно из-за возможного автоподхвата локальных plugins.
Данные Vaultwarden и runtime receipt/cache при откате не удаляются.

```bash
  /home/operator/.hermes/installs/e29f8e0c799cf788/environments/068b5b95ab254b268c324cffc5e78922/venv/bin/python \
  ops/compat_tests/catalog_native_unittest.py -v
```

Модельный и installed smoke используют тот же native Python/PYTHONPATH и требуют
`--execute`; модельный запрещает неявный повтор при существующем model-attempt.json.
Не удалять этот guard без проверки предыдущего исхода. Read-сценарии не создают
платежи/заказы, но возвращают приватные бизнес-данные: их полные ответы не публиковать.

Источники контрактов: существующие SG yandex-go-business/etm-ipro/saby-edo и
business-banking-api-integration; сервисная авторизация Saby дополнительно сверена
с [официальной документацией](https://saby.ru/help/integration/api/auth/service).
Доступность полных актуальных спецификаций ЭТМ/Точки через веб-инструмент не
подтверждена; успешные фактические чтения перечислены отдельно выше.
